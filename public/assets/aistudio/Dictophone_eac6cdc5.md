# Техническое задание: «Диктофон» для Android

**Версия:** 1.0
**Дата:** 24.10.2026
**Платформа:** Android 8.0+ (API 26+)
**Стек:** Rust (ядро), Tauri 2.x (оболочка приложения), JavaScript/TypeScript (UI)

---

## 1. Общее описание

Мобильное приложение-диктофон с записью аудио с микрофона устройства, хранением записей, их воспроизведением, редактированием метаданных и экспортом. Приложение построено на Tauri 2 для Android: нативный контейнер (Kotlin/Gradle) встраивает WebView, бизнес-логика реализована на Rust, интерфейс — на веб-технологиях (TypeScript + фреймворк UI).

### 1.1. Цели
- Надёжная запись аудио без потерь при сворачивании приложения (foreground service).
- Минимальное энергопотребление и нагрузка на процессор.
- Локальное хранение записей без обязательной облачной синхронизации.
- Простой и быстрый интерфейс: одна кнопка — старт записи.

### 1.2. Нецелевые требования (v1)
- Синхронизация с облаком.
- Распознавание речи (задел на будущее).
- Стриминг записей.
- iOS-версия.

## 2. Архитектура

```
┌────────────────────────────────────────────┐
│  WebView (UI)                             │
│  TypeScript + UI-фреймворк (Svelte/Vue)   │
└───────────────┬────────────────────────────┘
                │ Tauri IPC (invoke / events)
┌───────────────▼────────────────────────────┐
│  Rust-ядро (Tauri commands, state)        │
│  ├─ recorder   — управление записью       │
│  ├─ audio      — захват и кодирование     │
│  ├─ library    — каталог записей (SQLite) │
│  ├─ player     — воспроизведение           │
│  └─ export     — конвертация / шаринг     │
└───────────────┬────────────────────────────┘
                │ NDK / Platform APIs
┌───────────────▼────────────────────────────┐
│  Android: Foreground Service,             │
│  MediaStore, Runtime Permissions          │
└────────────────────────────────────────────┘
```

### 2.1. Ключевые компоненты

| Компонент | Ответственность | Реализация |
|---|---|---|
| `audio` | Захват PCM с микрофона, буферизация | Rust crate (см. §5) + Android AudioRecord через JNI/`tauri-plugin` |
| `recorder` | Состояния записи, тайминг, пауза | Rust, конечный автомат состояний |
| `codec` | Кодирование в AAC/OGG/FLAC/WAV | Rust (`mp4a`/`ogg_opus`/`flac` crates) |
| `library` | CRUD записей, поиск, теги | SQLite (`rusqlite`) |
| `player` | Воспроизведение, перемотка | Rust + системный медиаплеер или `rodio` |
| `export` | Экспорт, шаринг в другие приложения | Tauri plugin / Android `Intent.ACTION_SEND` |
| `ui` | Экраны, визуализация уровня | TypeScript |

### 2.2. Потоки (threads)
- UI-поток WebView — только отрисовка.
- RT-поток захвата — только запись в кольцевой буфер, без аллокаций и логирования.
- Поток кодирования — потребляет буфер, пишет файл.
- Все коммуникации — через `tokio` каналы / Tauri events.

## 3. Функциональные требования

### 3.1. Запись
- **FR-1.** Старт/остановка записи одной кнопкой на главном экране.
- **FR-2.** Пауза и возобновление записи в рамках одной сессии (файл дорабатывается).
- **FR-3.** Отображение в реальном времени: длительность записи, индикатор уровня (VU), индикатор клиппинга.
- **FR-4.** Именование записи:
  - при старте записи файлу присваивается автоимя по шаблону `Запись 2026-10-24 19-04-12` (шаблон настраивается);
  - сразу после окончания записи автоматически открывается диалог **«Сохранить запись»** с уже подставленным автоименем — его можно принять как есть или ввести своё;
  - введённое имя проверяется на уникальность в пределах текущего хранилища: при совпадении показывается ошибка `E_NAME_EXISTS` и предлагается ближайший свободный вариант (`Запись … (2)`, `… (3)`);
  - допустимо 1–100 символов; запрещены символы `/ \ : * ? " < > |`; имя из пробелов отклоняется (`E_NAME_INVALID`), краевые пробелы обрезаются автоматически;
  - подтверждение сохраняет запись в библиотеку; отмена («Позже» / системный «назад») сохраняет запись под автоименем, диалог можно вызвать повторно из карточки записи.
- **FR-5.** Запись продолжается в фоне (foreground service с уведомлением: название, таймер, кнопки «Пауза»/«Стоп»).
- **FR-6.** Защита от потери данных: запись буферизуется и периодически сбрасывается на диск; при аварийном завершении файл восстанавливается (журнал `.part` → финализация при старте).
- **FR-7.** Непрерывная запись ограничена только свободным местом; при нехватке — предупреждение и корректная остановка.
- **FR-8.** Опционально: обрезка тишины на концах (команды VAD в настройках).
- **FR-9.** При входящем звонке/потере фокуса: запись приостанавливается или продолжается (настройка).

### 3.2. Качество и форматы
- **FR-10.** Форматы записи (настройка «Качество»). **По умолчанию — MP3, 128 кбит/с (CBR), 44.1 кГц, расширение `.mp3`:**

| Профиль | Кодек | Битрейт | Частота | Использование |
|---|---|---|---|---|
| **По умолчанию** | **MP3** | **128 кбит/с (CBR)** | **44.1 кГц** | **универсальный, максимальная совместимость** |
| Высокое | FLAC | lossless | 48 кГц | интервью, музыка |
| Стандарт | AAC (LC) | 128 кбит/с | 44.1 кГц | компактный без потерь совместимости |
| Экономный | Opus | 32 кбит/с | 48 кГц | голосовые заметки |
| Совместимый | PCM WAV | 16-bit | 44.1 кГц | без сжатия, для редактирования |

- **FR-11.** Стереозапись (если доступно) / моно — настройка.
- **FR-12.** Предварительная амплификация и ограничитель (лимитер) — настройка «Усиление микрофона».

### 3.3. Библиотека записей
- **FR-13.** Список записей: имя, дата, длительность, размер, иконка формата.
- **FR-14.** Сортировка: по дате (новые/старые), по имени, по длительности; группировка по дням.
- **FR-15.** Поиск по имени и тегам.
- **FR-16.** Переименование (с той же проверкой уникальности имени, что в FR-4), удаление (с перемещением в корзину), восстановление из корзины (хранилище 30 дней).
- **FR-17.** Метаданные: теги/категории, избранное, заметка к записи.
- **FR-18.** Обложка-волна (waveform) — генерируется в фоне и кэшируется.

### 3.4. Воспроизведение
- **FR-19.** Плеер: play/pause, перемотка по таймлайну, скорость 0.5×–2.0×.
- **FR-20.** Отображение волновой формы с позицией воспроизведения.
- **FR-21.** Позиция воспроизведения и очередь восстановления после перезапуска приложения.
- **FR-22.** Управление с системной медиа-панели (MediaSession): кнопки play/next/prev, отображение названия.
- **FR-23.** Воспроизведение в фоне (продолжение при выключенном экране).

### 3.5. Редактирование (v1 — базовое)
- **FR-24.** Обрезка (trim): задать начало/конец, сохранить как копию.
- **FR-25.** Разделение (split) на несколько файлов по меткам.
- **FR-26.** Удаление фрагмента.
- Все операции — недеструктивные (исходник сохраняется, результат — новый файл).

### 3.6. Экспорт и шеринг
- **FR-27.** Экспорт в выбранный каталог через системный файловый п picker (`Storage Access Framework`).
- **FR-28.** Отправка в другие приложения через Android `ACTION_SEND` (мени интеграция).
- **FR-29.** Копирование внутреннего формата → публичный каталог `Music/Dictaphone` (MediaStore).
- **FR-30.** Переименование/конвертация при экспорте (выбор формата).

### 3.7. Настройки
- **FR-31.** Тема: светлая/тёмная/системная.
- **FR-32.** Язык интерфейса: русский, английский (i18n, `i18n`-набор ключей в JS).
- **FR-33.** Каталог хранения записей (внутреннее хранилище / внешнее).
- **FR-34.** PIN/биометрия на вход в приложение (опционально).
- **FR-35.** Экспорт/импорт настроек и базы (бэкап `.zip`).
- **FR-36.** Статистика: общее число записей, суммарная длительность, занятое место.
- **FR-37.** Формат и качество по умолчанию — **MP3 128 кбит/с**; профиль из FR-10 и шаблон автоимени настраиваются пользователем.

## 4. Нефункциональные требования

### 4.1. Производительность
- **NFR-1.** Задержка от нажатия «Запись» до начала захвата — ≤ 300 мс.
- **NFR-2.** Потребление CPU при записи AAC — ≤ 5% на среднем устройстве (2022 г.).
- **NFR-3.** Потребление памяти приложения — ≤ 120 МБ в фоне записи.
- **NFR-4.** Приложение запускается за ≤ 2 с на холодном старте.
- **NFR-5.** Волна (waveform) для записи часовой длительности строится ≤ 3 с (фоновый поток).

### 4.2. Надёжность
- **NFR-6.** Ноль потерь данных при: смерти процесса, разряде батареи, принудительной остановке.
- **NFR-7.** Все файловые операции — атомарные (запись во временный файл + rename).
- **NFR-8.** База SQLite с WAL и бэкапом перед миграциями.
- **NFR-9.** Обработка ошибок: каждая ошибка IPC → показ человекочитаемого сообщения + лог.

### 4.3. Совместимость
- **NFR-10.** Android 8.0 (API 26) — Android 15 (API 35).
- **NFR-11.** Архитектуры: `arm64-v8a` (обязательно), `armeabi-v7a` (желательно).
- **NFR-12.** Корректная работа на планшетах и в режиме split-screen.

### 4.4. Безопасность и приватность
- **NFR-13.** Все данные локальны; разрешения запрашиваются по требованию (runtime permissions).
- **NFR-14.** Разрешения: `RECORD_AUDIO`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_RECORDING`, `POST_NOTIFICATIONS`, `READ_MEDIA_AUDIO` (Android 13+).
- **NFR-15.** Нет сетевых разрешений в манифесте v1 (или изолированный feature-flag).
- **NFR-16.** WebView: отключён remote content, разрешён только `asset://`/`tauri://`.
- **NFR-17.** Секреты (если появятся) — через Android Keystore, не в JS.

### 4.5. Доступность
- **NFR-18.** Минимальный размер тап-цели — 48dp.
- **NFR-19.** Поддержка TalkBack: подписи к кнопкам, live-region для таймера.
- **NFR-20.** Контраст текста ≥ 4.5:1.

## 5. Технологии и библиотеки (Rust)

### 5.1. Ядро
- **Tauri 2.x** — оболочка, IPC, сборка под Android.
- **tokio** — async-рутинг команд и события.
- **serde / serde_json** — сериализация DTO между JS и Rust.
- **thiserror / anyhow** — типизированные ошибки ядра.

### 5.2. Аудио и кодирование
Вариант A (рекомендуемый): захват через нативный Android `AudioRecord` (JNI-мост в Rust), кодирование на Rust:
- `lame-mp3` / `mp3lame-encoder` (LAME) — **MP3 128 кбит/с, профиль по умолчанию**, в `.mp3`.
- `aac-encoder` / `mp4a` — AAC-LC в `.m4a`.
- `ogg_opus` / `opus` — Opus в `.ogg`.
- `flac` (claxon/rust-flac) — FLAC.
- `hound` — WAV/PCM.

Вариант B (упрощённый): захват через `cpal` (если на Android поддержан), кодирование — те же crates.

### 5.3. Хранение
- `rusqlite` (bundled) — каталог записей.
- `walkdir`, `serde` — сканирование каталогов.
- `symphonia` — декодирование/чтение метаданных для плеера и waveform.
- `hound` + ручной RMS/FFT (`rustfft`) — построение волновой формы.

### 5.4. Обмен с Android
- `tauri-plugin-android-permissions` (или собственный) — запрос разрешений.
- `jni` — вызовы: foreground service, MediaStore, share-intent.
- `tauri-plugin-fs`, `tauri-plugin-dialog` — доступ к файлам и SAF picker.
- `tauri-plugin-notification` — уведомления записи.

### 5.5. Инструменты
- `cargo fmt`, `cargo clippy -D warnings`, `cargo test`.
- `cargo-llvm-cov` — покрытие ядра (цель ≥ 70%).
- CI: GitHub Actions (build + test + Android bundle).

## 7. Модель данных (SQLite)

```sql
CREATE TABLE recordings (
  id            TEXT PRIMARY KEY,          -- uuid
  title         TEXT NOT NULL,
  file_path     TEXT NOT NULL,
  format        TEXT NOT NULL,              -- mp3 | aac | flac | opus | wav
  sample_rate   INTEGER NOT NULL,
  channels      INTEGER NOT NULL,
  duration_ms   INTEGER NOT NULL DEFAULT 0,
  size_bytes    INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,           -- unix ms
  note          TEXT,
  is_favorite   INTEGER NOT NULL DEFAULT 0,
  deleted_at    INTEGER,                    -- NULL = активна, иначе в корзине
  waveform_path TEXT                        -- кэш волновой формы (JSON/сжатый)
);

CREATE TABLE tags (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  name   TEXT NOT NULL UNIQUE
);

CREATE TABLE recording_tags (
  recording_id TEXT NOT NULL REFERENCES recordings(id) ON DELETE CASCADE,
  tag_id       INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (recording_id, tag_id)
);

CREATE INDEX idx_recordings_created ON recordings(created_at DESC);
CREATE INDEX idx_recordings_deleted ON recordings(deleted_at);

-- Уникальность имени (FR-4): только активные записи, корзина не участвует
CREATE UNIQUE INDEX idx_recordings_title_unique
  ON recordings(title) WHERE deleted_at IS NULL;
```

Миграции — версионные (`schema_version`), бэкап БД перед каждой миграцией.

## 8. IPC API (контракт JS ↔ Rust)

### 8.1. Команды `invoke`

| Команда | Аргументы | Возвращает | Описание |
|---|---|---|---|
| `recorder_start` | `{ profile, stereo, gain }` | `RecordingSession` | Начать запись |
| `recorder_pause` | — | `void` | Пауза |
| `recorder_resume` | — | `void` | Продолжить |
| `recorder_stop` | — | `Recording` + `suggestedTitle` | Остановить запись и вернуть автоимя для диалога |
| `title_check` | `{ title }` | `{ unique, suggestion }` | Проверка уникальности имени (дебаунс 200 мс) |
| `title_commit` | `{ id, title }` | `Recording` | Подтвердить введённое имя (ошибка `E_NAME_EXISTS` при конфликте) |
| `recorder_state` | — | `{ state, elapsedMs }` | Текущее состояние |
| `library_list` | `{ query?, sort, offset, limit }` | `Recording[]` | Список записей |
| `library_rename` | `{ id, title }` | `Recording` | Переименовать |
| `library_delete` | `{ id, permanent? }` | `void` | Удалить (в корзину/навсегда) |
| `library_restore` | `{ id }` | `Recording` | Восстановить из корзины |
| `library_set_meta` | `{ id, note?, favorite?, tags? }` | `Recording` | Метаданные |
| `player_play` | `{ id, positionMs?, rate? }` | `void` | Воспроизвести |
| `player_pause` / `player_seek` / `player_set_rate` | … | … | Управление |
| `waveform_get` | `{ id }` | `number[]` | Волна (нормализованная) |
| `export_recording` | `{ id, destUri, format? }` | `void` | Экспорт через SAF |
| `share_recording` | `{ id }` | `void` | Share-intent |
| `settings_get` / `settings_set` | … | `Settings` | Настройки |
| `stats_get` | — | `Stats` | Статистика |

### 8.2. События в JS

| Событие | Payload | Назначение |
|---|---|---|
| `recording://tick` | `{ elapsedMs, level, clipping }` | Таймер и VU (10 Гц) |
| `recording://state` | `{ from, to }` | Смена состояния (recording/paused/stopped/error) |
| `recording://error` | `{ code, message }` | Ошибка записи |
| `player://progress` | `{ positionMs, durationMs }` | Позиция плеера (10 Гц) |
| `library://changed` | `{ id, op }` | Инвалидация списка |
| `export://progress` | `{ id, percent }` | Прогресс экспорта |

DTO сериализуются через `serde`; типы TS генерируются (или поддерживаются вручную в `src/lib/ipc/types.ts`).

## 9. Состояния записывающего автомата

```
Idle ──start──▶ Recording ──pause──▶ Paused
  ▲                │  ▲                 │
  │                │  └────resume───────┘
  │             stop│                stop│
  ▼                ▼                     ▼
 Error ◀──codec/capture failure──── Stopping ──▶ Idle (событие library://changed)
```

- `Stopping`: остановка захвата → дозапись кодека (flush) → финализация файла → атомарный rename → запись в SQLite → событие.
- После успешного `Stopping` UI автоматически показывает диалог имени (FR-4); введённое имя фиксируется через `title_commit`, конфликт → `E_NAME_EXISTS`.
- При старте приложения: если обнаружен незакрытый `*.part` — финализация/восстановление (FR-6).

## 10. UX / Экраны

1. **Главная (Record)** — большая круглая кнопка записи, таймер крупно, уровень (VU-бар), индикатор профиля качества. Свайп влево → библиотека.
2. **Библиотека** — список с группировкой по дням, поиск, сортировка, долгий тап → контекстное меню (переименовать/удалить/шер/в избранное).
3. **Плеер** (модальный лист) — waveform, ползунок, скорость, кнопки, заметка.
4. **Редактор** — выделение диапазона, trim/split, превью.
5. **Настройки** — качество, поведение в фоне, хранилище, тема, язык, PIN, бэкап, статистика.
6. **Корзина** — список удалённых с таймером автоОчистки.

Требования к UX: рекорд-кнопка — не менее 96dp, доступность без свайпов для ключевых действий, off-screen элементы недоступны.

## 11. Ошибки и сценарии отказов

| Код | Сценарий | Поведение |
|---|---|---|
| `E_PERMISSION` | Нет `RECORD_AUDIO` | Диалог → переход в настройки Android |
| `E_MIC_BUSY` | Микрофон занят другой аппой | Сообщение + предложение закрыть |
| `E_STORAGE_FULL` | Мало места | Предупреждение при < 200 МБ, остановка при 0 |
| `E_CODEC` | Сбой кодирования | Остановка, сохранение `.part`, сообщение |
| `E_SERVICE` | Foreground service не запущен | Повтор попытки, фоллбэк на внутрипроцессную запись |
| `E_DB` | Повреждение SQLite | Восстановление из бэкапа, иначе рескан каталога |
| `E_NAME_EXISTS` | Имя файла уже существует | Подсветка поля + кнопка «Вставить свободное имя» (`suggestion`) |
| `E_NAME_INVALID` | Пустое имя, запрещённые символы, >100 символов | Сообщение под полем ввода |

Все ошибки локализованы (i18n-ключи `errors.*`).

## 13. Критерии приёмки (DoD)

- [ ] Запись стартует ≤ 300 мс, работает в фоне, переживает свайп приложения из списка.
- [ ] Убийство процесса во время записи не теряет файл (`.part` финализируется при старте).
- [ ] Новая запись по умолчанию сохраняется в **MP3 128 кбит/с** и открывается в стороннем плеере.
- [ ] После окончания записи автоматически показывается диалог имени с подставленным автоименем; неуникальное имя блокируется с предложением свободного варианта.
- [ ] 5 профилей качества записываются и воспроизводятся на Android 8 и Android 15.
- [ ] Библиотека: поиск/сортировка/корзина работают на 1000+ записей без лагов (скролл 60 fps).
- [ ] Плеер: перемотка и скорость работают, медиа-панель отображает управление.
- [ ] Экспорт и share отправляют файл в другие приложения.
- [ ] `cargo clippy -D warnings`, тесты ядра ≥ 70% покрытия, UI-тесты ключевых экранов.
- [ ] Приложение запускается на чистом устройстве без Google-аккаунта (sideload).
- [ ] Нет сетевых разрешений; все данные локальны.
- [ ] TalkBack озвучивает главные действия; тап-цели ≥ 48dp.

## 14. Риски и митигация

| Риски | Влияние | Митигация |
|---|---|---|
| Ограничения Android на фоновый запись (doze, OEM) | Потеря записи в фоне | Foreground service + `PARTIAL_WAKE_LOCK` + white-list battery optimization |
| Слабая поддержка аудио в Tauri Android | Задержка захвата | Собственный JNI-мост к `AudioRecord`, RT-поток без аллокаций |
| Размер бинарников (Rust + codecs) | Вес APK | `cargo` LTO, `opt-level=z`, раздельные `.so`, профили форматов по требованию |
| Разнобой WebView на старых Android | Баги UI | Минимум Chromium-фич, тесты на API 26-емуляторе |
| Потеря данных при миграции БД | Критично | WAL + бэкап перед миграцией + атомарные файловые операции |
